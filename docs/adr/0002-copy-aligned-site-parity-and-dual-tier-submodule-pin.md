# Copy-Aligned Site Parity and Dual-Tier Submodule Pin

The **Build Tutorial** (`site/` in `domesticmouse/EnvelopeFollower`) and the **Companion Site** (`reference/site/` in `domesticmouse/EnvelopeFollowerWithSkewLimiter`) will remain self-contained Astro Core workspaces kept aligned through copy-aligned shared modules and an automated `reference/` drift guard (`companion-parity` / Contract Group 7 in `site/src/lib/site-contract.ts`) rather than a published shared npm package or cross-submodule Vite imports. Submodule pinning follows a dual-tier policy: `reference/` and root `README.md` (the **Living Context Map**) track the live aligned **Companion Site** HEAD (`164f50f` and subsequent lockstep parity bumps), while historical tutorial prose (`site/src/content/tutorial/**`, `PotentialImprovements.md`, and `docs/research/reference-github-trail.md`) stays permanently anchored to `8ad81d0` as the immutable **Decision Trail** snapshot ([PR `#32`](https://github.com/domesticmouse/EnvelopeFollowerWithSkewLimiter/pull/32)).

## Considered Options

- **Publish a shared npm package or extract a monorepo workspace:** Rejected because both repositories are standalone static GitHub Pages sites with independent `site/package-lock.json` CI caches and zero package-registry release pipeline. Sharing roughly ten infrastructure files (`tokens.css`, `fonts.css`, `dialog-chrome.ts`, `mermaid-client.ts`, `search-modal.ts`, `panel-svg-shared.ts`, `remark-double-dollar-math.ts`, `MermaidHydrator.astro`, `tsconfig.json`, and `vitest.config.ts`) across an external npm boundary adds versioning and release overhead while obscuring intentional site-specific divergences (`1380px` 3-column workbench vs. `1200px` curated container, MDX **Prompt Blocks** vs. single-source **Static Passthrough**).
- **Import directly from `reference/site/` via Vite path aliases or `fs.allow`:** Rejected because cross-submodule imports couple TypeScript checking and Astro builds to an initialized `reference/` checkout and its `node_modules/` tree, reintroduce Vite `fs.allow` parent-directory coupling that `site/astro.config.mjs` intentionally avoids, and turn upstream **Companion Site** refactors into immediate build breakages before parity review.
- **Single-tier live pin (rewrite all `8ad81d0` tutorial citations on every bump):** Rejected because `site/src/content/tutorial/**`, `PotentialImprovements.md`, and `docs/research/reference-github-trail.md` document a fixed hardware and **Companion Site** engineering run concluding at [PR `#32`](https://github.com/domesticmouse/EnvelopeFollowerWithSkewLimiter/pull/32) (`8ad81d0`). Mass-rewriting `163` historical `8ad81d0` citations on each parity bump would silently invalidate quoted line numbers, file counts, and **Decision Trail** evidence.

## Consequences

- **Copy-aligned shared surface with automated drift detection:** Shared tokens, font imports, client modules, remark plugins, and tooling configs stay vendored inside `site/` and are audited against `reference/site/` by Contract Group 7 (`companion-parity`) whenever `reference/` is populated, keeping intentional divergences documented while catching accidental regressions.
- **Dual-tier Contract Group 6 link verification:** `site/src/lib/site-contract.ts` verifies pinned `EnvelopeFollowerWithSkewLimiter/{blob,tree}/<sha>/...` links against `reference/`'s git object database (`git cat-file -t <sha>:<subpath>`), allowing historical `8ad81d0` **Decision Trail** URLs and live `164f50f` **Living Context Map** URLs to coexist while continuing to reject unpinned `main` or `HEAD` branch URLs and requiring root `README.md` to reference the current `reference/` HEAD short SHA.
- **Low-churn lockstep bumps:** Advancing `reference/` for future **Companion Site** parity releases only updates the `reference` gitlink, root `README.md`, and any changed copy-aligned files in `site/`, leaving all `13` tutorial MDX pages, `PotentialImprovements.md`, and `docs/research/reference-github-trail.md` untouched.
